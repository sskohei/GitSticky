# メモと同期の保護

## 利用手順

同期先は **非公開リポジトリだけ** 選択できます。接続確認、同期の開始、各書き込み・削除の前にRust側でもGitHubの公開範囲を取得して確認します。公開範囲を取得できない場合も処理を中断します。新規設定の自動同期は無効です。既存の自動同期設定は保持しますが、同期用の暗号鍵がなければ同期しません。

最初の端末では、設定画面でリポジトリとブランチを選び、「新しい鍵を作成」で同期用の暗号鍵を作ります。「鍵を表示する」で表示し、パスワード管理アプリなどへ控えてから「暗号鍵を登録」を押してください。ほかの端末では **同じ鍵** を登録します。すでに暗号化されたメモがある場合は、候補の鍵で全ファイルを復号できることを確認してから保存します。登録を誤った場合は「同期用の暗号鍵を再登録」で修正できます。その場合も、既存の暗号文すべてを復号できる鍵だけを受け入れます。既存の暗号文を別の鍵で再暗号化する鍵ローテーションには対応していません。

鍵はリポジトリとブランチの組み合わせごとに管理します。暗号文を別のリポジトリ・ブランチへコピーしても、そのまま復号はできません。別の同期先へ移す際は、元の端末にメモが読める状態で新しい同期先を登録してください。端末故障や再インストールに備え、同期用の鍵はアプリの外にも安全に保管してください。鍵を失った場合、GitHub上の暗号文を復元する機能はありません。

## 暗号化の範囲

- 端末内では、タイトル・Markdown本文・タグをAES-256-GCMで暗号化してSQLiteへ保存します。ランダムな端末専用鍵はWindowsのユーザー単位DPAPI、AndroidのKeystoreで保護します。GitHubの認証情報や同期用の鍵とは別の保存領域を使い、GitHubから切断してもメモの鍵を削除しません。
- GitHubへは送信前にAES-256-GCMで暗号化します。256ビットの同期用鍵と、暗号化ごとに生成する96ビットのnonceを使用します。認証対象にはリポジトリ・ブランチ・メモIDを含め、ファイルの入れ替えや改ざん、誤った鍵を拒否します。
- 同期ファイル名は引き続き `notes/<UUID>.md` ですが、ファイルの内容は `schemaVersion: 3` の暗号化JSONです。復号後は従来のMarkdown形式です。同期するMarkdownは1ファイル5MB以下です。旧バージョンやGitHubのWeb画面で本文を編集することはできません。
- UUID・ローカルの色・ピン・更新日時・同期状態などの管理情報、GitHub上のファイル名・サイズ・コミット履歴は暗号化されません。起動中の画面やメモリ、同じOSユーザー権限で実行される不正プログラムからの保護は対象外です。
- Androidの自動バックアップ・端末移行は無効にします。Keystoreの鍵だけ復元できずメモが読めなくなる状態も避けます。端末間の移行には暗号化したGitHub同期と、控えた同期用の鍵を使ってください。

## 既存データの移行

初回に既存SQLiteのタイトル・本文・タグを同じトランザクションで暗号化します。保存先と既存メモのrevision・dirty・同期状態は保持します。鍵の保存に失敗した場合はロールバックし、すでに暗号化されたDBの鍵がなくなった場合は、新しい鍵を生成して上書きしません。平文のページを整理するため、`secure_delete` と `VACUUM` を使います。中断後に再試行できるよう、整理の完了状態も記録します。

GitHub上の既存Markdownは、正しく読み取れたものを同期中に暗号化します。誤った鍵や壊れた暗号文が1件でもある場合は、書き込みやローカルへの反映を始める前に同期を中断します。不正な従来Markdownは上書きせず、同期エラーとして表示します。全ファイルの移行が完了した端末では、同じ同期先で再び平文が現れた場合も同期を拒否します。

**過去のGit履歴・コピー・既存バックアップの平文は消えません。** SSDやOSのスナップショットからの物理的な復元防止も保証しません。機密メモは新しい非公開リポジトリへ同期してください。過去の履歴を削除・書き換える操作は自動で行いません。暗号化後に旧バージョンへ戻して同じローカルDBを開かないでください。

## 依存関係と再確認

Vitestは4.1.12以降、tinypoolは2.2系、minimatchは11系へ更新しました。SQLxを0.9へ更新し、`libsqlite3-sys 0.39.1`（SQLite 3.54.1）を使用します。SQLxの公開版の上限に対応するため、SQLx SQLiteドライバーを同梱し、依存バージョンの制約だけを変更しています。変更点と削除条件は `src-tauri/vendor/sqlx-sqlite/GITSTICKY-PATCH.md` を参照してください。SQLプラグインを廃止し、RustがDB・マイグレーションを所有するため、フロントエンドから任意のDBをロードする権限も不要になりました。

`pnpm audit` は開発用を含めて警告0件です。Cargo.lockのOSV照合ではSQLite・ZIP・RSAの従来の警告は解消していますが、8パッケージに通知が残ります。bincode・paste・proc-macro-error・zbus_names・zvariant・zvariant_deriveは保守終了の通知、glibはLinux向け依存のメモリ安全性の問題、crypto-bigintは旧Stronghold移行用の依存に含まれるタイミング問題です。これらを「全依存関係に問題なし」と扱わず、上流の修正版・置換を引き続き追跡してください。暗号化したメモの保存・同期はStrongholdを使用しません。

自動検証では、ローカル移行後のDBに平文が含まれないこと、再起動・鍵の欠落・誤鍵・保存失敗からの再試行、改ざんと別メモへの暗号文の入れ替え、端末間の同じ鍵による復号、移行後の平文拒否、公開先拒否、移行と編集競合、復号失敗時に既存データを変更しないことを確認します。実際のGitHubアカウント・Android実機を使う確認は別途必要です。
